# 新对话空状态居中还原

> 状态：已实现（方案 A：`newConversationEmptyState.less` + 布局契约测试）
> 关联截图：用户标注的「新对话」右侧红框区域（标题 + 建议问题 + 输入框）  
> 关联回归：`3597d0e`（抽取 `NewConversationEmptyState` 后，居中样式失效）

## 一、需求（Requirements）

### 1.1 问题

在「新对话」页（侧栏第一项），右侧工作区里的对话空状态（红框内容：标题「让你的知识触手可及」、建议问题、输入框）被挤到左上角，下方与右侧留白过大。

该问题在教师端与学生端同时存在。两端共用同一套前端路由与组件（`/platform/creatChat`、`/platform/knowledge-bases/:kbId/creatChat` → `creatChat.vue`），不是两套独立页面。

原来的版本是整块内容在右侧工作区内水平 + 垂直居中；用户认为居中更好看，要求还原。

### 1.2 目标

把知识库对话空状态（右侧红框）还原为最初的居中布局：在右侧可用视口内水平居中、垂直居中。

### 1.3 成功标准

1. 教师账号打开「新对话」：红框内容块位于右侧内容区视觉中心（不是贴顶贴左）。
2. 学生账号打开「新对话」：同上。
3. 从知识库上下文进入的新对话（`kbCreatChat`）行为与全局新对话一致。
4. 标题文案、建议问题、输入框、模型选择、发送行为保持不变；本次只修布局。
5. 有消息的既有会话页（`chat/:id`）布局不受影响。

### 1.4 非目标

- 不改标题文案（已由「标题精简」规格处理）。
- 不重新设计建议问题样式、颜色、动效。
- 不改侧栏、菜单、权限、教师/学生差异化功能。
- 不做移动端专项重做（现有断点行为保持可接受即可）。

## 二、规格（Spec）

### Problem Statement

新对话空状态本应通过 `.dialogue-wrap` 的 `flex: 1` + `justify-content: center` + `align-items: center` 在右侧工作区居中。抽取 `NewConversationEmptyState` 后，样式从父组件的 `.dialogue-wrap` 改为 `:deep(.dialogue-wrap)`。Vue scoped CSS 的 `:deep` 会编译成「祖先选择器 + 后代选择器」，而 `.dialogue-wrap` 恰好是子组件根节点：父 scope 属性打在该根上，后代选择器匹配不到，居中规则实际未生效，内容退回文档流默认左上对齐。教师端与学生端共用该组件，因此两端同时回归。

### Solution

恢复空状态外壳在右侧工作区中的水平 + 垂直居中，使样式再次作用在 `.dialogue-wrap`（或其等价根容器）上，并保证 `flex: 1` 能吃满 `platform-route-outlet` 的剩余高度。优先把布局样式收回到空状态外壳自身（或与外壳同目录的样式模块），避免父组件 `:deep` 打在子组件根上再次失效。保留现有标题、建议问题插槽、composer 插槽与 SSR 测试缝。

### User Stories

1. As a teacher opening「新对话」, I want the empty-state block centered in the right pane, so that the page looks like the original product layout.
2. As a student opening「新对话」, I want the same centered empty state, so that role differences do not change this layout.
3. As a user entering new chat from a knowledge-base context, I want the same centering, so that both creatChat routes stay consistent.
4. As a returning user, I want title / suggested questions / composer unchanged, so that fixing layout does not alter conversation behavior.
5. As a developer, I want a regression test that the empty-state root carries the centering layout contract, so that a future extract cannot silently drop it again.

### Approaches considered

| 方案 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| A. 样式收回外壳（推荐） | 在 `NewConversationEmptyState`（或同目录 less）声明 `.dialogue-wrap` / `.dialogue-answers` / `.dialogue-title` 的布局规则；`creatChat.vue` 只保留建议问题等页面私有样式 | 根因修复；外壳自包含；两端一次修好 | 需从 `creatChat.vue` 迁一小段 CSS |
| B. 父组件去掉 `:deep` | 改回 `.dialogue-wrap[data-v-parent]` 形式，依赖「子根继承父 scope」 | 改动面极小 | 布局仍散落在父页；再抽取易再踩坑 |
| C. `creatChat.vue` 加单根 wrapper | 外层再包一层 `flex:1` 居中容器 | 不依赖 scoped 细节 | 多一层 DOM；与「外壳即公共表面」目标重复 |

**推荐：方案 A。**

### Implementation Decisions

- 居中定义：右侧工作区（`.platform-route-outlet` 内、侧栏以右）可用矩形的水平居中 + 垂直居中；内容块本身仍 `max-width: 960px`，不拉满全宽。
- 修复入口：`frontend/src/views/creatChat/newConversationEmptyState.ts` 及其样式归属；`creatChat.vue` 删除已失效的 `:deep(.dialogue-wrap|answers|title)` 布局规则（或改为只保留无法下沉的页面私有规则）。
- 教师端 / 学生端：无分叉实现；同一组件、同一路由覆盖两端。
- 保持 `data-testid="new-conversation-empty"` 与 questions / composer 插槽，避免破坏现有 SSR 文案测试。
- 不改 `chat/index.vue` 有消息会话布局。
- 不改 i18n、API、权限、菜单。

### Testing Decisions

- 保留现有标题 / 建议问题 / composer 的 SSR 断言。
- 新增布局契约测试（优先静态源码或可渲染外壳断言）：空状态根节点（或外壳样式模块）必须声明 `flex: 1`、`display: flex`、`justify-content: center`、`align-items: center`（或等价且可证明的居中约定）。目的是防止再次用失效的 `:deep` 挂在子根上。
- 手工验收：教师账号 + 学生账号各打开一次「新对话」，确认红框内容居中；再抽查 `kbCreatChat`。
- 不强制引入 Playwright/视觉回归（除非仓库已有同类基建且成本很低）。

### Out of Scope

- 标题文案、品牌名、多语言 slogan 调整。
- 建议问题内容、刷新逻辑、骨架屏动效重做。
- 输入框、模型选择、Agent 切换、附件、@ 提及。
- 侧栏「新对话」吸顶与历史列表。
- 已有会话消息流页面的布局。
- 单独为教师端 / 学生端做两套 UI。

### Further Notes

- 原始可用对照：`368c68b` / `cd05f3e` 时代 `creatChat.vue` 内联 `.dialogue-wrap { flex:1; display:flex; justify-content:center; align-items:center; }`。
- 回归提交：`3597d0e refactor(新对话): 抽取空状态外壳组件并升级为 SSR 渲染测试`。
- 截图红框仅作定位，不在 UI 中复现。
