# 上游同步评估：Tencent/WeKnora v0.8.2

> 状态：**待拍板**（仅评估，未开 sync 分支）  
> 日期：2026-10-01  
> 本地 HEAD：`e963401a`（`main`，`VERSION=0.8.1`）  
> 上游 remote：`upstream` → https://github.com/Tencent/WeKnora.git  
> 本地已钉基座：`v0.8.0`（换基完成并合入 `main`）  
> 上游最新发布：[`v0.8.2`](https://github.com/Tencent/WeKnora/releases/tag/v0.8.2)（2026-09-24）  
> `v0.8.2` 之后 `upstream/main`：约 **102** 个提交（**本评估不建议追**）

---

## 1. 一句话结论

**值得跟到 `v0.8.2`，但不是小补丁；最大硬风险是 schema 迁移号 `000091`–`000098` 与川农教学迁移撞车。**  
相对上次（无共同祖先的 0.7→0.8 换基），这次已有 `merge-base = v0.8.0`，技术路径更清晰，仍应按 **钉 tag + `sync/upstream-v0.8.2` + A–G 垂直重放**，不要追 `upstream/main`。

## 3. 硬风险：迁移号撞车（Ticket 0 必须先解）

### 3.1 冲突表

| 版本号 | 本地（HEAD，川农） | 上游（`v0.8.2`） |
| --- | --- | --- |
| 000091 | `tenant_default_agent` | `mcp_tool_enabled` |
| 000092 | `tenant_notes` | `mcp_metadata` |
| 000093 | `announcements` | `browser_authorization` |
| 000094 | `platform_identity_flags` | `memory_consistency` |
| 000095 | `workspace_ownership_anomalies` | `memory_vector_search` |
| 000096 | `single_active_share_link` | `dingtalk_stream_only` |
| 000097 | `tenant_notes`（修订） | `session_fork` |
| 000098 | `announcements`（修订） | `fork_snapshot_lease` |
| 000099–000110 | （无） | MCP endpoints / artifacts 表 / sandbox / host workspace / IM locale 等 |

`v0.8.0` 官方止于 **000090**。两边各自从 **091** 起分叉；现网 QA 记录显示开发库曾到 **98**（川农内容）。

### 3.2 两条升级路径含义

| 路线 | 含义 | 做法草稿 |
| --- | --- | --- |
| **Route 1 空库** | 新 volume，无历史 version 行 | 基座用上游 `091`–`110`；川农迁移 **整体顺延为 `111+`** 后重放 |
| **Route 2 克隆升级** | 库里 `091`–`098` 已是川农 SQL，**不是**上游同号内容 | **禁止**直接跑上游同名文件；需「补齐上游 091–110 语义 + 登记版本」的桥接方案，再继续 `111+` |

桥接方案需在 Ticket 0 写成可执行剧本（推荐优先评估）：

1. **运维一次性脚本**：在克隆库上按依赖顺序执行上游 `091`–`110` 的 SQL（或等价 DDL），再把 `schema_migrations` 拨到与代码树一致；川农代码侧文件改名为 `111+` 且内容与已落库 schema 对齐。  
2. **或** 保留历史号不动、把上游缺的 schema 做成「川农号段之后的补偿迁移」——但必须证明与官方 `v0.8.2` 终态 schema 一致，且避免日后再次撞号。

**未拍板桥接方案前，不要开大规模重放。**

## 5. 上游 `v0.8.0`→`v0.8.2` 对川农有意义的变更

### 5.1 强烈建议纳入（安全 / 正确性）

| 主题 | 与川农关系 |
| --- | --- |
| `feat(security): whitelist-only outbound` | 公网部署出站面；与 SSRF 基线同向 |
| 共享空间跨空间访问修复、scoped authorization 统一 | 勿削弱教学空间隔离；合入后回归成员/共享路径 |
| 路径穿越拒绝（local prefix / task / wiki sort） | 安全基线 |
| 文档解析卡住 / OCR / docreader 超时杀进程等修复 | 课堂上传稳定性 |
| MCP `!:` 持久化工具目录与短路由 | **BREAKING 面在 MCP**；教学默认可关，但代码合入后勿让学生配置入口漏出 |

### 5.2 必须带着合入、但默认关闭或收紧的产品面

| 主题 | 策略建议 |
| --- | --- |
| Toolbox（skills / MCP / browser 连接管理） | 学生菜单隐藏；教师按需 |
| BrowserSkill / 本地 Chrome 连接 | 默认关；viewer 无入口 |
| Artifacts 库页 + 删除产物 | **viewer 后端拒绝 + 前端无入口**（I7 升级验收） |
| Host OS sandbox / Lite 绑宿主目录 | 教学部署保持关；文档标明非课堂默认 |
| 会话 fork / reasoning 控件 / 模型目录拆分 | 教师可用；学生 UI 不新开能力 |

### 5.3 可选 / 延后

- 日语 locale（`ja-JP`）、网站 docs 大迁移、多种 web-search provider  
- `upstream/main` 上的 AnyDoc **0.2.4**（见下）、`feat(auth) 仅限邀请注册档` 等——**不进本轮基座**，单独立项

### 5.4 anydoc 特例

| 树 | anydoc pin |
| --- | --- |
| `v0.8.2` | **0.1.9** |
| 本地 `main` | **0.2.4**（`d321a01c`） |
| `upstream/main` | 已有升级到 0.2.4 的提交 |

换基到 `v0.8.2` 后会**掉回 0.1.9**，必须把本地 anydoc 0.2.4 适配（pin / lock / model 穷尽 match / OCR 文案）作为独立 Ticket 重放；**不要**为此提前追整段 `main`。

## 7. 不建议的合入方式

1. **追 `upstream/main`**：多约 102 个未发布组合变更；与「钉 release」冲突。  
2. **在现网库上直接 `migrate` 上游 `091`–`098`**：version 行已存在且 SQL 语义不同，结果未定义。  
3. **只 cherry-pick 安全 PR**：迁移与 MCP/模型重构依赖链长，易漏。  
4. **先合 chat UI 再合权限 / 产物拒绝**：学生封闭面会空窗。

---

## 8. 推荐策略（相对 v0.8.0 规格的增量）

沿用 [`docs/上游同步-v0.8.0规格.md`](./上游同步-v0.8.0规格.md) 的 A–G 顺序与 I1–I15 合同，调整如下：

### 阶段 0 — 基座 + 迁移剧本（阻塞项）

1. `git fetch upstream --tags`（已做）  
2. `git worktree` / 分支：`sync/upstream-v0.8.2` ← **`v0.8.2`**  
3. 定稿 **迁移桥接 + 川农 `111+` 顺延** 方案，并在空库验证 goose/migrate 线性可跑  
4. 记录上游测试基线（`docs/sync-v0.8.2-baseline.md`）

### 阶段 1 — 垂直域重放（TDD）

| 序 | 域 | 相对 v0.8.0 轮次的增量焦点 |
| --- | --- | --- |
| A | 成员 / 邀请 viewer-only | 共享空间授权修复回归；邀请 UI |
| B | SuperAdmin / 教师 / 平台身份 | `container` / user 类型合并 |
| C | 学生纯问答 | **产物库 + 附件 + toolbox/MCP/browser 入口** |
| D | 笔记 + 公告 | 迁移改号后的 API/页 |
| E | 品牌 / 登录 / 菜单 / 默认 Agent | `menu` / `Login` / `AgentList` 重构对齐 |
| F | 新对话空状态 | `creatChat` + `chat/index` |
| G | 部署默认 | `invite_only`、沙箱关、**anydoc 0.2.4 重放**、compose 默认 |

### 阶段 2 — QA 两路

- Route 1：空库 + `WITH_ANYDOC=1`  
- Route 2：**克隆**开发库 volume；只在克隆卷验证桥接迁移（禁止写源卷、禁止对源卷 `down -v`）

### 阶段 3 — 合并

仅在你明确说「合并」后：`sync → main`；不 force-push。
