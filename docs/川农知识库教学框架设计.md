# 川农知识库 · 教学使用框架设计（v1）

> 状态：已确认（2026-08 grilling 会话产出）
> 适用范围：基于 WeKnora 上游（Tencent/WeKnora）二次定制的四川农业大学教学知识库部署
> 相关定制：登录页/侧栏川农品牌化、隐藏上游 GitHub 外链、`invite_only` 注册模式、课程邀请固定 viewer、学生不可见成员名单

## 1. 背景与目标

教师（空间所有者）提供预装教学文档的知识库；学生通过邀请链接注册账号，只能**问答查询**，不能修改课程知识库与系统配置，学生界面也不提供文件下载入口。学生拥有课程空间内各自私有的个人会话；需要整理材料时，自行复制回答内容到本地文档。前期小规模（1-2 门课，约 60-120 名学生，课后作业查询为主），以能开课、可运维为第一优先级。

**一句话架构**：云服务器上运行一套 WeKnora，按课程建空间、预装文档库、配好模型；学生通过限时邀请链接注册（对课程知识库 viewer 只读）进空间，只使用课程 Agent 问答，需要的内容自行复制。

## 2. 架构总览

```
┌─ 云服务器（公网可达，docker-compose 全套）──────────────┐
│  WeKnora(app + postgres + redis + docreader + frontend) │
│  Ollama: bge-m3 向量化（本机，免费）                     │
└──────────────────┬─────────────────────────┘
                   │ 多次使用邀请链接（角色=viewer）
                   ▼
   学生点链接 → 注册账号 → 自动入课程空间 → 课程 Agent 问答
                   │
    学生个人会话（课程空间内各自私有）
    仅问答；需要的内容由学生自行复制
```

## 3. 架构决策记录（ADR）

### ADR-001 空间拓扑：方案 A，邀请链接直进课程空间

- **决策**：教师在自己的课程空间生成**多次使用、固定为 viewer 的限时邀请链接**，学生点链接注册后直接进入课程空间；一门课一个空间，知识库长期沉淀。注册期结束后教师核对名单并撤销链接。
- **理由**：学生体验最短（注册即用）；上游已实现多用途邀请链接（`registerByInvite` / `getInvitationByToken`）；组织（共享空间）模式的跨空间共享链路较绕，不采用。
- **被否决的替代**：方案 B（自主注册 + 组织共享）——路径长一步，且为省少量模型费用不值得。

### ADR-002 注册门槛：invite_only

- **决策**：系统设置中将 `auth.registration_mode` 设为 `invite_only`，登录页"创建账户"入口随之隐藏，唯一注册途径为教师生成的邀请链接。
- **理由**：减少无关人员自行注册；invite_only 模式下邀请链接仍可完成注册（上游登录页已处理 `?token=` 分支）。邀请链接可被转发，不能当作校内身份认证，必须配合名单核验和及时撤销。

### ADR-003 学生角色：viewer 对课程知识库只读

- **决策**：邀请链接指定角色 viewer。
- **已核实的能力边界**：
  - ✅ 可：对话、切换/选用空间内模型、预览文档解析内容、使用课程 Agent、手动复制回答文本
  - ❌ 不可：建库、上传文档、改模型配置、下载原始文档、生成或下载会话产物文件、整库导出（功能不存在）
- **理由**：v1 严格限定为问答使用。课程原始文档不提供下载入口，也不为学生启用生成可下载文件的 Skill、MCP 或沙箱能力。

### ADR-004 身份约定

- **决策**：要求学生用户名 = 真实姓名 + 学号后四位（如 `张剑1234`），邮箱随意（QQ 邮箱即可）。
- **边界**：这只是填写约定，不是身份认证；持有邀请链接的人可以自行填写任意姓名、学号和邮箱。
- **配套流程**：成员列表仅教师可见；注册期结束后教师按课程名单核对，移除不明账号并撤销邀请链接。
- **理由**：在不接入校内统一认证的 v1 阶段，以教师人工核验换取最低开发量。

### ADR-005 模型供给：v1 教师统一配置

- **决策**：v1 由教师（空间 admin）在空间级配置全部模型，学生零配置直接用。
- **已核实的机制**：模型是空间级基础设施（`models` 表仅 `tenant_id`，无 user 维度）；viewer 可看可用、不可增删改，模型凭据写入为 Admin+ 专属。
- **v2 候选**："学生自带 key"——在空间模型之上加 user 维度的 key 覆盖层（学生填了用自己的 key 计费，没填回落到空间 key）。中等工作量（schema + 权限 + 对话链路）。

### ADR-006 模型选型

| 用途 | 选型 | 说明 |
|---|---|---|
| 对话（生成） | OpenAI 兼容 **chat completions** | 后端统一走 `/chat/completions`；OpenAI 新 responses 接口**不支持**（已核实），亦无必要 |
| 向量化（检索） | **本机 Ollama + bge-m3** | 免费、中文效果好、查询向量不出本机；教师机器/云服务器均可承载 |
| 文档解析 | **MinerU**（云 API） | 上游原生支持（`mineru_endpoint` / `mineru_api_key` / OCR/公式/表格开关），扫描版 PDF 依赖它 |

### ADR-007 部署：公网云服务器

- **决策**：迁移至轻量云服务器（预估 50-100 元/月），docker-compose 整体搬迁；域名（可选）+ HTTPS 由服务器侧解决。
- **理由**：系统跑在教师个人电脑上是全框架最脆弱环节（关机/断网/离开校园网即不可用）。

### ADR-008 密码找回：v1 手动重置，v2 自助

- **已核实的现状**：后端无任何邮件发送能力，也无 forgot-password 路由；但系统管理员重置链路完整——`POST /system/admin/users/reset-password`（按邮箱 + 新密码，校验强度策略，**同时吊销该用户全部会话**，密码不进日志），前端入口在 系统设置 → 账户与访问 → 重置密码。
- **v1 流程**：学生联系教师 → 教师在系统设置中重置为临时密码 → 学生登录后自行修改。
- **前提**：教师账号须为系统管理员；部署时用 `WEKNORA_BOOTSTRAP_SYSTEM_ADMIN_EMAIL=<教师邮箱>` 引导提升（幂等，只升不降）。**两个限定**：① 仅当系统尚无任何 SystemAdmin 时才提升，已有管理员则静默跳过——迁移旧数据卷时须先确认这一点；② 只提升已注册用户，不会创建用户，教师必须先完成注册。
- **v2**：自助邮件重置（SMTP 发验证码），需后端引入邮件能力，约 2-3 tickets。

### ADR-009 v1 开发清单

1. **课程 Agent 打磨**：预绑课程知识库 + 教学提示词（口径限定、要求引用来源）。上游机制已支持：Agent 预绑的库在学生选中 Agent 时**自动预选**。先配置验证，不够顺再动代码。
2. **使用统计（简单清单）**：空间成员列表加两列——累计提问数、最后活跃时间。目的：识别"谁还没用起来"，供教师评价学生整体参与情况。统计仅到计数粒度、不做提问明细——学生对话内容对教师不可见（隐私 + 开发量三倍）。
3. **新会话默认选中课程 Agent**：全空间生效（含教师本人），实现为空间级默认值。
4. **课程邀请固定 viewer**：本部署的共享邀请链接接口固定写入 viewer，后端拒绝 owner/admin/contributor，前端不展示角色选择；教师协作者使用单独的成员管理流程授权。
5. **成员名单仅教师可见**：空间成员列表改为 Admin+ 才能访问，学生端隐藏入口，后端不得向 viewer 返回其他成员的用户名、邮箱或学号信息。
6. **学生纯问答模式**：课程 Agent 不绑定可生成文件的 Skill/MCP；会话产物下载接口（`/sessions/:id/artifacts*`）上游对 Viewer+ 开放，需**后端同样拒绝 viewer** 调用，不能只靠前端隐藏入口。

### ADR-010 v1 明确不做

- 防刷限额：靠使用统计观察，出现真实滥用再界定"正常基线"后开发
- 学生自带 key：v2（ADR-005）
- 忘记密码自助：v2（ADR-008）
- 系统内新手引导：用课程群图文说明代替
- 提问明细报表：隐私风险大于收益
- 学生会话文档生成与下载：v1 仅支持复制回答文本，后续按教学需要再评估

### ADR-011 数据备份：v1 必做

- **决策**：每日备份数据库（pg_dump）和文档存储目录；同时备份 `SYSTEM_AES_KEY`、`.env`、`config/config.yaml` 以及实际启用的自定义配置/Skill。备份加密后异盘存放，保留 N 份。
- **恢复验收**：上线前至少做一次从备份恢复到空环境的演练，确认可以登录、打开课程文档并完成一次问答。以后每次修改存储后端或密钥策略时重新演练。
- **理由**：数据库中的模型凭据依赖 `SYSTEM_AES_KEY` 解密；只备份数据库和文件，在密钥丢失后仍无法恢复可用系统。

### ADR-012 隐私告知

- **决策**：学生使用说明中写明"提问内容将发送给第三方大模型服务用于生成回答"；学生不可查看课程成员名单及他人的邮箱、学号和会话。
- **会话可见性边界**：学生对话内容仅该学生本人可见，教师/管理员**不可查看**任何学生的具体提问与回答；教师端仅获得整体使用统计（累计提问数、最后活跃时间，见 ADR-009-2），可据此评价学生的整体参与情况。此边界写入学生使用说明（见第 5 节）。

## 4. v1 上线 Runbook

1. **云服务器部署**：安装 Docker → 迁移 docker-compose 栈（postgres 数据卷一并迁移）→ 配置域名/HTTPS → 确认公网可达
2. **教师先注册**：临时保持公开注册（`self_serve`），启动后由教师注册账号——**此窗口内任何拿到域名的人都能自助注册，教师完成注册前不要对外公布域名**
3. **系统管理员引导**：`.env` 设 `WEKNORA_BOOTSTRAP_SYSTEM_ADMIN_EMAIL=<教师邮箱>` 后重启，并**确认教师账号已提升为 SystemAdmin**（注意：若迁移的旧数据卷中已存在 SystemAdmin，该变量会静默跳过，需先移除旧管理员或改由旧管理员手动提升）
4. **关闭自由注册**：教师注册完成后立即将 `auth.registration_mode` 设为 `invite_only`，收缩公开注册窗口
5. **模型配置**（空间设置 → 模型管理）：
   - 对话模型：OpenAI 兼容接口（baseURL + key + 模型名）
   - 向量化：Ollama `bge-m3`（服务器装 Ollama 拉模型）
   - 解析：MinerU 云 API（申请 key，配置 OCR/公式/表格开关）
6. **建知识库**：上传课程文档，跑通解析与索引
7. **建课程 Agent**：绑定知识库 + 写教学提示词（限定回答范围、要求引用）
8. **完成 v1 开发项**：默认课程 Agent、使用统计、邀请固定 viewer、成员名单教师可见、学生纯问答模式（见 ADR-009）
9. **关闭学生自助建空间**：设置 `WEKNORA_TENANT_SELF_SERVICE_CREATION_ENABLED=false`
10. **备份与恢复演练**：备份 pg_dump、文档目录、`SYSTEM_AES_KEY`、`.env`、`config/config.yaml`，在空环境完成一次恢复验收
11. **生成限时邀请链接**：设置 → 空间成员 → 多次使用邀请；确认后端只允许 viewer，并记录链接到期时间
12. **验收走查**：用学生账号完整走查——注册 → 入空间 → 默认进入课程 Agent → 提问 → 看引用 → 复制回答；确认看不到成员名单、建库入口、原始文档及会话产物下载入口
13. **越权验收**：确认课程空间无法生成高于 viewer 的邀请链接，viewer 直接调用成员列表、文件下载及会话产物下载接口会被拒绝或得到脱敏结果
14. **开放注册窗口**：向课程群发送邀请链接和使用说明（见第 5 节）
15. **注册结束收口**：教师按课程名单核对成员，移除不明账号并立即撤销邀请链接

## 5. 学生使用说明（模板）

> **川农知识库·三步上手**
> 1. 点击老师发的邀请链接，填写信息注册（用户名请填"真实姓名+学号后四位"，如 `张剑1234`）
> 2. 进入后选择"XX课程助手"，知识库已自动选好
> 3. 直接提问；回答会标注来源文档，可点击查看出处。需要整理材料时，请自行复制回答内容
>
> 说明：提问内容将发送给第三方大模型服务用于生成回答；请勿在提问中填写个人敏感信息。你的提问内容仅自己可见，老师看不到具体对话；老师只能看到整体使用统计。
> 忘记密码：联系老师重置（临时密码），登录后请尽快自行修改。

## 6. 已核实的技术事实（设计依据）

- 邀请链接：`?token=` 分支在登录页完整处理，invite_only 下仍可注册入空间
- 邀请链接身份边界：token 是持有者凭证，不绑定校内身份、指定邮箱或学号；v1 必须人工核验成员名单
- 原始文档下载接口：上游后端为 `Contributor()` + KB 写权限守卫；川农 v1 学生界面不提供下载入口
- 会话产物：上游具备 Skill 产物下载能力，且 `/sessions/:id/artifacts*` 接口对 Viewer+ 开放；川农 v1 不为学生启用文件生成能力，前后端同时阻断 viewer 的产物下载
- Agent：同空间成员原生可见可用；预绑库随 Agent 自动预选
- 知识库选择：localStorage 持久化，跨会话记忆
- 模型：空间级，viewer 可看可用不可改；凭据写入 Admin+ 专属
- 对话模型接口：仅 `/chat/completions` 形态
- MinerU：原生支持（含云 API 参数）
- 密码：无自助找回；系统管理员可重置他人密码并吊销全部会话

## 7. v2 Backlog（按优先级）

5. 学生会话文档生成与下载
