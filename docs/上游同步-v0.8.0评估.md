## 1. 一句话结论

**值得合入，但是一次大版本跃迁（0.7.2 线 → 0.8.0），不能当小补丁 cherry-pick。**  
川农教学定制与上游 v0.8.0 有约 **64 个重叠文件**（冲突热点），另有约 **147 个教学专属文件**可相对干净地带走。建议用 **「以 v0.8.0 为新基座 + 按教学不变量做 TDD 重放」**，不要对无关历史强行 `merge --allow-unrelated-histories`。

---

## 2. 版本关系（事实）

| 项 | 值 |
| --- | --- |
| 本地 `VERSION` / `frontend/package.json` | `0.7.2` |
| 定制起点 | `368c68b`「川农知识库教学定制起点（基于 WeKnora 上游快照）」 |
| 与上游 tag 的 git merge-base | **无**（快照导入，历史与 `upstream` 不连通） |
| 相对 `v0.8.0` 的「上游独有」提交量级 | 约 2900+（按连通祖先估算，不可当线性 rebase 数） |
| `v0.8.0` 之后 `upstream/main` | 约 8 个 commit（MCP 工具开关、飞书图、sandbox 工具统一、小程序 i18n 等） |
| 定制起点 → 当前 | 约 65 个川农相关 commit |

含义：本地不是「从官方 tag 拉分支再开发」，而是「导入快照后叠教学改动」。同步策略必须按 **内容/行为合入**，不能假设干净的 `git merge upstream/main`。

## 3. 上游 v0.8.0 对川农有意义的变更

### 3.1 强烈建议纳入（安全 / 正确性 / 部署）

| 主题 | 为何与川农相关 |
| --- | --- |
| OIDC JWKS 验签 + `/auth/oidc/start` | 若未来接校园 IdP，属安全基线 |
| SSRF / 出站 URL 加固、共享 IP 分类 | 公网部署安全 |
| `invite_only` 下邀请链接「先登录再入空间」+ 已注册用户 auto-accept | 与川农「邀请制入课」强相关；需与 **viewer-only** 不变量一起验收 |
| 部署能力键过滤菜单（Lite / 精简构建） | 避免学生端露出未注册模块 |
| Postgres compose 默认安全检查修复 | 部署稳定性 |
| Local 沙箱后端 **删除**；Docker 沙箱 **默认关闭、需 opt-in** | **BREAKING**；对照 `docs/川农学生端封闭发布集成与沙箱密钥.md` 重写部署剧本 |

### 3.2 可选纳入（产品能力，非教学硬需求）

- Skill 沙箱运行时（Docker / E2B / Cube）+ 租户技能目录  
- 跨会话长期记忆（`/api/v1/memory/*`）  
- anydoc 进程内 Office 解析、GitLab / 腾讯 IMA 数据源、LiteLLM、Exa/Metaso 搜索  
- Chat artifacts / 问题大纲 / 时间戳、文档自动打标签  
- 可选复杂密码策略  

教学场景若坚持「学生纯问答」，长期记忆与沙箱技能可默认关；但合入代码后仍要确认 **viewer 边界** 不被上游默认权限放宽。

### 3.3 与川农定制冲突热点（重叠约 64 文件）

**后端（约 36）** — 合入时冲突概率最高：

- `tenant_invitation*` / `tenant_member*` / `user*` / `auth*` / `tenant*` handler+service+types  
- `router` / `routes_auth_tenant` / `routes_chat` / `routes_agent`  
- `session_knowledge_qa*`（学生附件 / 产物边界可能触及）  
- `config.go` / `container.go` / `errors.go` / audit / migration 测试  

**前端（约 25）** — 二次冲突高：

- `Login.vue`、`menu.vue`、`Input-field.vue`  
- `TenantMembers.vue`、`AgentList/Editor`、`auth` store、`settingsAccess`  
- i18n 四语、`router`、`SystemSettings`、chat artifacts / botmsg  

**部署（约 2+）**：`.env.example`、`docker-compose.yml`

### 3.4 相对干净、可整块搬迁的教学专属面（约 147 文件）

- 笔记 `/me/notes`、公告板、川农 docs / CONTEXT / tickets  
- SuperAdmin / 教师平台身份、教学二态成员 UI（`teachingMembership`、`formatRoleLabel`）  
- 新对话空状态居中 / 标题精简（`creatChat/*`）  
- 学生端隐藏附件、「添加到知识库」、仅默认 Agent 等行为（合入后要用测试钉死）

## 4. 不建议的合入方式

1. **`git merge upstream/main --allow-unrelated-histories`**：冲突海量、难回滚、难做 TDD。  
2. **只 cherry-pick 上游个别 PR**：基线差太大，依赖/迁移号对不上。  
3. **先合 UI 再合权限**：教学不变量是安全边界，顺序反了。

---

## 5. 推荐合入策略（TDD）

### 目标态

新分支基于 **`upstream/v0.8.0`（或再含 main 上那 8 个修复）**，再把川农行为 **按垂直域重放**，每域「测试先绿 / 实现后绿」。

### 阶段 0 — 基座（约半天）

1. `git fetch upstream --tags`（已完成）  
2. `git checkout -b sync/upstream-v0.8.0 upstream/v0.8.0`  
3. 记录基线：跑上游自带 `go test` / 前端关键测试（能跑多少算多少，记下失败清单）  
4. 写入「川农不变量清单」（见下）作为验收合同  

### 阶段 1 — 先钉不变量测试（TDD RED → 搬实现 → GREEN）

按优先级拆垂直域；每域独立 commit 序列：

| 序 | 垂直域 | 先写/移植的测试（RED） | 再搬实现直到 GREEN |
| --- | --- | --- | --- |
| A | 成员二态 + 邀请 viewer-only + 历史降权 + Owner 恢复审计 | 现有 `tenant_invitation*` / `tenant_member*` / 教学迁移 / P1 规格相关测试 | service/handler/router 权限面 |
| B | SuperAdmin / 教师能力 / 平台身份标签 | `user_capability*`、教师列表、auth 相关测试 | `user` / system teacher / 前端 identity |
| C | 学生纯问答边界 | 附件/产物 deny viewer 的 handler 测试；前端隐藏入口契约测试 | chat/artifacts/Input-field |
| D | 笔记 + 公告 | `/me/notes`、`announcements` API/前端测试 | 整块专属文件多，冲突少 |
| E | 品牌与登录 / 菜单 / 默认 Agent | Login、menu、AgentList 行为测试 | 前端定制 |
| F | 新对话空状态 | `creatChat.test.ts` 标题 + 居中契约 | `creatChat` / Less |
| G | 部署：compose / readiness / 迁移阻断 / 沙箱 opt-in | 部署能力键、migration readiness 测试；对照封闭发布文档改 env | `docker-compose`、`.env.example`、bootstrap |

每域门禁：

- 该域测试全绿  
- 相关上游回归不全红（至少该包）  
- 教师 + 学生各一条手工冒烟（最后总验收再做全量）

### 阶段 2 — 上游新能力策略（显式开关）

合入代码后默认：

- Docker 沙箱：**保持关闭**，直到对照封闭发布文档验证  
- 长期记忆：课程空间默认关  
- 复杂密码：按校内策略再开  

用配置/能力键表达，而不是删上游代码。

### 阶段 3 — 总验收（发布前）

1. 迁移 `000080`–`000090`（及 SQLite 对应）在空库 + 现网备份副本演练  
2. 教师：建课 / 邀请 / 成员二态 / 公告  
3. 学生：注册入课 / 仅默认 Agent / 问答 / 笔记；确认无成员名单、无附件、无产物下载  
4. 前端重建镜像 + Ctrl+F5
