## 一、需求（Requirements）

### 1.1 问题

川农知识库基于 WeKnora 上游快照二次开发，本地 `VERSION` 为 `0.7.2`，与官方 git 历史无共同祖先。上游已发布 **v0.8.0**（含沙箱、记忆、邀请链路、SSRF/OIDC 等大量变更）。若继续停在旧基线，拿不到上游安全与正确性修复；若无计划硬合，会破坏教学不变量与现网可用性。

### 1.2 目标

1. 将代码基座换到官方发布点 **`v0.8.0` tag**（不跟漂 `upstream/main`）。  
2. 把川农教学行为完整重放到新基座上，且每一垂直域以 **先测试、后实现** 的方式验收。  
3. 换基期间 **`main` 继续可部署、可上课**；仅在同步分支验收通过后再切换。  
4. 上游新能力默认对教学部署 **安全关闭或显式 opt-in**，避免学生端行为漂移。

### 1.3 成功标准

1. 存在分支 `sync/upstream-v0.8.0`，其上游内容以 `v0.8.0` 为唯一基座（可用 `git merge-base` / tag 说明验证）。  
2. 下列川农不变量在同步分支上全部有自动化测试覆盖，且测试通过（见 §2.4）。  
3. 空库与「现网备份副本」均能完成 schema 迁移 `000080`–`000090`（及对应 SQLite），教学数据迁移在 `AUTO_MIGRATE=true/false` 下均可跑通或按既有规格 fail-closed。  
4. 教师端 + 学生端手工冒烟清单全部勾掉（Ticket QA）。  
5. `VERSION` / 文档 / 部署剧本标明教学部署基于 WeKnora `0.8.0` + 川农补丁。  
6. 合并进 `main` 后，前端镜像可重建，现网可按剧本升级。

### 1.4 非目标

- 不在本次把基座跟到 `upstream/main`（含 post-0.8.0 的 8 个 commit）。  
- 不开启 Docker 沙箱、长期记忆、复杂密码为教学默认。  
- 不重做品牌视觉、不新开教学功能。  
- 不用 `merge --allow-unrelated-histories` 一把梭。  
- 不删除上游新模块源码「图省事」；用配置 / 能力键关闭。

## 二、规格（Spec）

### Problem Statement

本地仓库由「上游快照 + 约 65 个川农 commit」构成，与 `Tencent/WeKnora` 无 merge-base。上游 `v0.8.0` 相对 `v0.7.2` 线引入沙箱 BREAKING、邀请/入空间流程变化、十余个 schema 迁移，以及与川农改动重叠的约 64 个热点文件（成员/邀请/auth/router/Login/menu 等）。直接 merge 或零散 cherry-pick 无法保证教学 viewer-only、学生纯问答与部署 fail-closed 等不变量，也会让后续开发失去稳定基线。

### Solution

采用 **「钉死 v0.8.0 新基座 + 按垂直域 TDD 重放川农不变量」**：

1. 从 `upstream/v0.8.0` 检出独立分支 `sync/upstream-v0.8.0`。  
2. 先记录上游基线测试结果。  
3. 按 Ticket 顺序：每个垂直域先移植或编写失败测试（RED），再从当前 `main` 搬入实现直至 GREEN，并保持该域相关上游回归不全红。  
4. 上游新能力以默认关闭策略接入。  
5. 全量冒烟与迁移演练通过后，再合并 `main` 并更新部署文档。

权威行为合同以 `CONTEXT.md`、`docs/川农知识库教学框架设计.md`、既有权限/笔记/公告/居中规格为准；本规格只规定 **换基过程与验收门禁**，不改写那些产品不变量本身。

### User Stories

1. As an operator, I want the sync branch based on tagged `v0.8.0`, so that the runtime is reproducible and not a floating main tip.  
2. As a developer, I want teaching invariants enforced by tests before porting UI/code, so that merges cannot silently weaken viewer-only or student boundaries.  
3. As a teacher, I want member invites to still only create students (`viewer`), including after upstream invite-only / auto-accept changes.  
4. As a SuperAdmin, I want teacher appointment and inherited teacher capability to keep working on the new base.  
5. As a student, I want pure Q&A (no member list, no attachment upload, no artifact download, default course agent only) after the upgrade.  
6. As a student, I want notes and announcements to keep working.  
7. As a user opening「新对话」, I want the centered empty state and simplified slogan preserved.  
8. As an operator, I want Docker sandbox off by default and teaching migration readiness fail-closed behavior preserved.  
9. As a deployer, I want `main` usable until sync is green, so classes are not blocked mid-upgrade.  
10. As a maintainer, I want a written ticket order and done criteria, so subsequent work stays stable and reviewable.

### Approaches considered

| 方案 | 做法 | 结论 |
| --- | --- | --- |
| A. 钉死 `v0.8.0` + TDD 垂直重放（推荐） | 新分支换基，按域测试驱动搬川农 | **采用** — 稳定、可验收 |
| B. 跟 `upstream/main` | 多 8 个未发布组合变更 | 拒绝 — 与「稳定可使用」冲突 |
| C. unrelated-histories 硬合 | 一次 merge | 拒绝 — 冲突不可控 |
| D. 只拣安全 PR | 无共同祖先 | 拒绝 — 依赖/迁移对不齐 |

### Implementation Decisions

#### 基座与分支

- Remote：`upstream` → `https://github.com/Tencent/WeKnora.git`（已存在则复用）。  
- 基座 commit：`refs/tags/v0.8.0`（发布点，不以 `upstream/main` 为合并目标）。  
- 工作分支：`sync/upstream-v0.8.0`。  
- 保护：`main` 在 Ticket QA 完成前不强制切流；同步期间 `main` 仅合紧急热修，大功能尽量延后以免双搬。

#### 重放方法（每个垂直域）

1. **RED**：在 sync 分支加入/移植该域测试；确认失败原因是「缺川农行为」而非测试本身损坏。  
2. **GREEN**：从当前 `main`（或等价路径）搬入最小实现集，解决与 v0.8.0 的接口/迁移冲突。  
3. **回归**：跑该包/相关前端测试；记录仍失败的上游测试并分类（环境 / 已知 / 需修）。  
4. **提交**：按中文 Conventional Commits；一域可多 commit，但不得跨域搅在一起。

禁止用「先整树拷贝再删测试」代替 RED→GREEN。

### Testing Decisions

- **最高层缝优先**：已有 HTTP/集成测试、前端 SSR/契约测试优先移植；不为换基新造 mock 框架。  
- **每域 RED 证据**：ticket 报告须含失败输出摘要（缺行为），再含 GREEN 输出。  
- **不变量映射**：每个 I1–I15 至少挂到一个自动化测试或（仅限 I13 品牌类）明确手工检查项。  
- **迁移**：空库 + 备份副本各跑一次；`AUTO_MIGRATE=true` 与 `false` 覆盖教学迁移门禁。  
- **手工 QA**：教师/学生清单见 Ticket QA；不过 QA 不得合 `main`。  
- **上游失败分类**：环境问题记录后可跳过；行为回归必须修或升为显式豁免（需写进 ticket 备注并经确认）。

### Out of Scope

- 合入 `v0.8.0` 之后的 `upstream/main` commits（可另开「post-0.8.0 热修评估」）。  
- 新教学功能、RBAC 角色扩展、校内 IdP 全面上线。  
- 重写官方 website-docs 全站。  
- 性能压测与多机集群沙箱。  
- 强制开启沙箱/记忆作为课堂默认体验。

### Further Notes

- 重叠热点文件清单见评估文档 §3.3；实施时以实际 diff 为准。  
- 中文 commit 规范：`type(scope): 中文简述`。  
- 预估：数天到一周+；权限/邀请域（Ticket A）最耗时。
