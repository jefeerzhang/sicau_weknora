# 川农知识库 · 学生笔记功能设计（v1）

> 状态：已确认（2026-08-30 grilling 会话产出）
> 关联：[教学框架设计](川农知识库教学框架设计.md)（笔记是学生端唯一可写数据面）
> 模仿先例：user-favorites（000047，per-(user,tenant) 隔离）+ env-vars（000089，/me 前缀路由）

## 1. 背景与定位

学生在学习课程资料时需要记录个人笔记，Markdown 书写。**纯个人私有**：教师与其他学生均不可见（含计数），延续 ADR-012 隐私立场。这是学生端唯一可写的数据面。

## 2. 已确认决策

| # | 决策 | 内容 |
|---|---|---|
| N-1 | 归属可见性 | 纯个人私有；后端按 (tenant_id, user_id) 隔离；**不提供任何按空间列全体笔记的端点**——教师不可见在结构上成立，而非策略上约束 |
| N-2 | 入口 | 侧栏新增「我的笔记」→ `/platform/notes` 独立页：左侧笔记列表（按更新时间倒序）+ 右侧编辑/预览 |
| N-3 | 编辑器 | Markdown 源码编辑 + 预览切换；复用 manual-knowledge-editor 的工具栏与安全渲染管线（safeMarkdownToHTML → marked → sanitizeHTML） |
| N-4 | 保存 | **自动保存**（v2 修订，原手动保存因「忘存丢稿」废弃）：停止输入 1.5s 防抖落库；新建走**延迟创建**（首次自动保存才 POST，空草稿切走不留痕）；自动保存失败保留未保存态并随输入重试；切换/离开**冲刷优先**（先落库，仅失败拦截）；关闭页面保留原生确认。保留手动按钮与 Ctrl+S 作为强制冲刷 |
| N-5 | 贴图 | v1 支持：粘贴/工具栏上传图片，个人图片独立端点存取 |
| N-6 | 标题 | 无独立标题字段；**列表端点由服务端派生 `title` 字段**（首个 `#` 标题 → 无则首个非空行截 50 字 → 空笔记为空串，前端显示"无标题"）。派生在服务端做，客户端无需拉正文 |
| N-7 | 限额 | 每人 200 篇；单篇内容 ≤ 1MB；每张图片 ≤ 2MB；每人图片 ≤ 200 张（全部为常量校验） |
| N-8 | 教师可见性 | 完全不可见，使用统计也不含笔记维度 |

## 3. 数据模型（迁移 000092）

```sql
CREATE TABLE IF NOT EXISTS tenant_notes (
    id         VARCHAR(36) PRIMARY KEY,
    tenant_id  BIGINT      NOT NULL,
    user_id    VARCHAR(512) NOT NULL,   -- 与 sessions.user_id 同规格
    content    TEXT        NOT NULL DEFAULT '',
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE INDEX IF NOT EXISTS idx_tenant_notes_user
    ON tenant_notes (tenant_id, user_id, updated_at DESC);

CREATE TABLE IF NOT EXISTS tenant_note_images (
    id         VARCHAR(36) PRIMARY KEY,
    tenant_id  BIGINT      NOT NULL,
    user_id    VARCHAR(512) NOT NULL,
    mime       VARCHAR(100) NOT NULL,
    bytes      BYTEA       NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE INDEX IF NOT EXISTS idx_tenant_note_images_user
    ON tenant_note_images (tenant_id, user_id);
```

两张表同属迁移 `000092`（归 ticket 06 一次建齐，ticket 07 只写逻辑）。

## 3.1 图片访问与生命周期（ticket 07）

- **读取**：`GET /me/notes/images/:id` 仅 **owner 本人**可读（非本人 404，不泄露存在性）。前端本就走 authed fetch → objectURL hydration，capability URL 折衷无收益，已废除——N-1 的结构性隐私主张由此闭环
- **删除**：`DELETE /me/notes/images/:id`（owner），主动释放配额
- **GC**：删除笔记时，扫描该用户剩余笔记的图片引用集合，GC 仅被被删笔记引用的图片（best-effort，失败不影响删除）
- **缓存**：图片响应带 `Cache-Control: private, max-age=31536000, immutable` + `ETag`（id 即内容版本），避免每次预览重复 authed fetch
- **类型校验**：白名单 image/png|jpeg|gif|webp，且**嗅探 magic bytes**（Content-Type 可伪造）

图片访问采用 capability URL（36 位不可猜测 UUID 即访问凭证），读取端点要求登录但不校验归属——v1 折衷，文档明示。

## 4. API（全部 `/me/notes`，登录成员即可；user 从 auth ctx 取，前端不传）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /me/notes | 列表：id / **title（服务端按 N-6 规则派生）** / updated_at（不含 content） |
| POST | /me/notes | 新建 {content}，校验篇数与字节数限额 |
| GET | /me/notes/:id | 读取单篇（owner 校验） |
| PUT | /me/notes/:id | 保存 {content}（owner 校验 + 字节数校验） |
| DELETE | /me/notes/:id | 删除（owner 校验） |
| POST | /me/notes/images | 上传图片（multipart ≤2MB；magic bytes 白名单校验；数量校验）→ {url} |
| GET | /me/notes/images/:id | 图片字节（**仅 owner，非本人 404**；带 private immutable 缓存头 + ETag） |
| DELETE | /me/notes/images/:id | 删除图片（owner），主动释放配额 |

## 5. 前端

- menu.ts 增「我的笔记」项（无需 capability 开关）+ 路由 `/platform/notes` + 四语言文案
- `views/notes/MyNotes.vue`：列表 + 编辑器。编辑器工具栏与预览从 manual-knowledge-editor 抽取复用（textarea + wrapSelection 工具栏 + safeMarkdownToHTML 预览）
- 图片：粘贴/按钮上传 → 插入 `![](url)`；预览时对笔记内图片 URL 做 authed hydration（仿 hydrateProtectedFileImages）
- 未保存守卫：路由离开 + beforeunload

## 6. v1 明确不做

- 文件夹/标签/全文搜索/笔记分享/提交作业（v2 教学闭环候选）/公式渲染（v2 可升级 KaTeX 管线）/复杂配额
- 多标签页并发编辑一致性：PUT 全量覆盖 last-write-wins，不做 If-Match/ETag 冲突检测（后写覆盖先写，静默；自动保存提高覆盖频率，接受）
- 自动保存的失败自动重试退避（v1 为「下次输入触发重试」）
- 成员移除时的笔记/图片清理：数据保留，随租户删除时一并清理

## 7. 实现偏离与再评估触发（有意识决策记录）

- **图片直存 PG BYTEA，绕过 FileService 抽象**（local/tos/cos/s3/minio 那套）：v1 换取 per-user 门禁与限额的极简实现；单用户理论上限 200×2MB≈400MB。**再评估触发**：单租户图片总量 > 5GB，或图片接口 P95 明显劣化 → 迁 FileService。000084 已有 BYTEA 先例（小向量），本偏离量级更大，故留此记录防止被当惯例
- **/me/notes 仅挂 web 登录认证路径**：000089 的注释警告 IM 路径会在 user_id 存合成租户账号（同 workspace 所有 IM 用户共享一个 user_id）——笔记路由绝不注册到 IM 认证下，否则整个 IM 侧的笔记会混进一个 owner
- **限额为 count-then-insert，存在并发竞态窗口**：两个并行的第 200/201 篇可能都通过。教学场景风险低，明确接受近似；实现放事务内执行缩小窗口，ticket 06 含并发验证项

## 8. 验收标准（要点）

- 学生 A 创建/编辑/删除自己的笔记；学生 B 与教师均无法通过任何端点访问 A 的笔记（含枚举：不存在列全体端点）
- 超限（第 201 篇、>1MB 内容、>2MB 图片、第 201 张图）均被 400 拒绝并提示
- 刷新不丢稿：未保存离开有确认；保存后列表顺序按更新时间倒序
- 贴图：粘贴截图 → 上传 → 预览可见；刷新后仍可见
- 图片归属：学生 B 拿到学生 A 的图片 URL 直读 → 404；A 删图后配额即时释放
- 删笔记 GC：删除仅被一篇笔记引用的图片后，该图片 URL → 404 且配额回收
